# Benchmark Marker and Report Design

## Status

Historical decision record. The README and generated rustdoc describe the
current API.

## Goal

Provide a generic benchmarking pipeline for PocketIC-based tests without
owning application benchmark suites, labels, thresholds, or CI policy.

The primary measurements come from canister execution context rather than host
wall-clock timing:

- instructions;
- Wasm heap bytes;
- stable-memory bytes;
- a reserved total-allocation counter.

## Marker protocol

Canister code emits compact log lines:

```text
ICTK|<label>:<start-or-end>|<instructions>|<heap_bytes>|<memory_bytes>|<total_allocation>
```

`ICTK` is the default configurable prefix. The parser accepts configured
prefixes but attaches no application semantics to them.

Labels are opaque non-empty strings. A start and end marker form a span only
when their labels match. Repeated and nested labels pair by stack order within
each label.

## Processing pipeline

The host-side pipeline is deliberately explicit:

```text
captured output or fetched logs
  -> parsed events and malformed-marker diagnostics
  -> paired spans, unpaired markers, and invalid spans
  -> suite and cross-suite aggregates
  -> optional comparison with a compatible previous run
  -> CSV, Markdown, and JSON report artifacts
```

Parsing does not silently discard malformed configured markers. Strict mode
can additionally report non-marker log lines.

Counter deltas use checked subtraction. A decreasing counter produces an
invalid span rather than wrapping. This matters because instruction counters
are meaningful only within compatible execution scopes.

## Aggregation

Spans derive a suite from the first label path segment by default, or use one
fixed configured suite. Reports retain raw spans and compute per-label totals,
sample counts, and averages.

The cross-suite aggregate uses an internal key. Rendering that key as `ALL`
does not collide with an authored suite literally named `ALL`.

Comparisons operate on matching aggregate identities and record both absolute
and percentage changes when a previous compatible run exists.

## Output ownership

Report paths are caller-owned. Run-directory helpers choose deterministic
names and find compatible previous metadata, but they do not reserve paths or
impose a process-wide lock.

Concurrent writers must use unique destinations or synchronize only the exact
shared output path.

## Boundary

ic-testkit owns the generic marker protocol, parsing, validation, aggregation,
comparison, and report serialization. Downstream repositories own:

- which operations are benchmarked;
- label naming conventions;
- topology and fixture setup;
- regression thresholds;
- pass/fail policy;
- artifact retention and CI presentation.

The canister-side `Performance` helper emits markers. It does not parse reports
or depend on PocketIC runtime management.
